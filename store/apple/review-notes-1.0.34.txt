FlyRight 1.0.34 — a feature release on top of 1.0.33. No new permissions, no new purchases, no change to the account model, no change to the ATT usage described below. It does add one new app extension, described first.

NEW APP EXTENSION — SHARE EXTENSION (com.shanavasshaji.flyright.expo-sharing-extension):

FlyRight now appears in the system share sheet for travel documents, so a boarding pass can be sent to the app from Wallet, Mail, Files or Photos. The extension accepts only pkpass/pkpasses, PDF, image, file-URL, URL and plain-text attachments (see its activation rule), writes the shared file into the app's App Group container, and hands it to the app's existing import screen. It shows no UI of its own beyond the standard share sheet, makes no network calls, and reads nothing else from the host app. The App Group (group.com.shanavasshaji.flyright.wallet) is used only for that hand-off.

WHAT CHANGED SINCE 1.0.33:

- Boarding passes kept on a trip: the barcode read from a scanned or imported pass (IATA BCBP, PDF417/Aztec/QR) is stored with the trip and can be shown again at the gate. The pass screen redraws the code from the stored payload, so it works with no network, and raises screen brightness while it is open, the way Wallet does. The traveller can remove a stored pass from that screen.
- The pass is synced to the traveller's other devices with the rest of the trip, and the seat, sequence and booking reference it carries fill themselves in.
- Sharing a picture of a ticket: a screenshot or photo can now be shared into FlyRight everywhere a PDF could be. A pass shared from Wallet attaches to a trip that already exists instead of creating a duplicate.
- Imports read from a screenshot keep their route when the airline's printed layout is damaged, and an import waits for every leg's lookup before saving.
- Live Activities for followed trips: a traveller can allow a specific follower to see their trip on that follower's Lock Screen. It is off by default and the traveller turns it on per person.
- The World map opens on the whole world again, and trip photos no longer fail to upload after an app update.

HOW TO REVIEW:

DEMO ACCOUNT — HOW TO SIGN IN: Settings tab -> "Sign in or create account" -> enter the email above -> tap Continue -> tap "Use another method" -> "Sign in with your password" -> enter the password. No email code is needed for this account.

- Boarding pass on a trip: My travels tab -> open the upcoming Finnair AY1331 trip -> the "Boarding pass" card shows the barcode; tap it for the full-screen gate view (tap the code itself to stand a PDF417 stripe on end). Airplane mode does not affect it.
- Adding one: My travels -> "+" -> "Scan ticket or boarding pass" for the camera, or "Upload a ticket PDF or screenshot" to pick a file. Any IATA boarding-pass barcode works.
- The share extension: from Files or Photos, share a .pkpass or a ticket PDF/screenshot and choose FlyRight; the import screen lists the flights it read.
- Compensation verdict and claim letter, no account needed: Claims tab -> "See a demo verdict" -> "Generate my claim".
- Account deletion: Settings -> the account row -> Delete account.

UNCHANGED FROM 1.0.33: App Tracking Transparency is asked once and, if authorized, the IDFA is used solely for install attribution of our own marketing (Layers SDK); analytics carry an install id, screen names and purchase events only, never flight, claim, note or photo content, and declining changes nothing in the app. The app reports an anonymous launch event to Expo's EAS Insights (install id, app version, platform, OS version). The camera is used for boarding-pass scanning, the photo library for uploading a ticket and attaching trip photos or updates, and push for flight status, claim deadlines, trip updates from people the user follows and the store release notice. Location is never requested (a bundled notification SDK references the API, hence the purpose string). The app is fully usable without an account; live flight lookups require one and are capped per day. iPad is supported in both orientations.
